# 生存模式打造两架飞行器：规划

状态：**规划稿，未实施**。等你确认第 8 节的决策后再动手。

## 1. 现状（已核实）

| 项 | 现状 |
| --- | --- |
| 配方 | 工程里**根本没有 data/ 目录**（glob 全库无命中），也就是说两架飞机目前**没有任何配方** |
| 获取途径 | 仅创造物品栏（ModCreativeTabs 里只有 little_bird 与 apache 两个入口） |
| 物品 | battlefield:little_bird、battlefield:apache，均 stacksTo(1)，已有物品模型与 16x16 图标 |
| 弹药 | 现在**无限**：阿帕奇的备用弹仓按时间自动补给、小鸟也有自动补弹计时器；无需任何物品 |
| 损伤 | 有血量（小鸟 80 / 阿帕奇 120），但**无法修复**；被打爆直接 discard，**什么都不掉** |
| 回收 | **没有任何把飞机收起来的交互**（右键只能登机） |

结论：现在的生存体验是「创造物品栏拿出来 → 坏了就没了」，需要补的是**材料链 + 生存闭环**两件事。

## 2. 设计目标

1. 小鸟 = **中期**目标：大致相当于「一整套铁装 + 铁砧 + 附魔台」的投入；
2. 阿帕奇 = **中后期**目标：约小鸟的 2.2 倍，并且卡在**钻石 + 末影珍珠**（也就是要去过下界/见过末影人）；
3. 材料全部取自**原版物品**，不引入需要挖矿新矿的设定；
4. 让「组装」这件事读起来像造飞机：**零件 → 机身 → 整机**，而不是 9 个铁块一拍。

## 5. 解锁与成就

- 配方书：沿用原版行为（拿到任一材料即解锁对应配方），不做额外限制；
- 追加两个进度（advancement）：首次合成小鸟（第一架飞机）、首次合成阿帕奇（武装到了牙齿）；
- 创造物品栏同时列出 9 个零件，方便调试。

## 6. 生存闭环的四个缺口（这才是「能不能玩」的关键）

### 6.1 回收（必须有）
现在飞机放下就再也收不回来。建议：**潜行 + 空手右键** = 打包回物品（不做新工具，交互成本最低）。
打包时把**当前血量写进物品 NBT**，这样一个被打残的飞机会以一个「残血物品」回到背包（与 6.4 修复配套）。

### 6.2 弹药（需要你拍板）
现在两机都是**无限弹药**（自动补给）。三个选项：
1. **保持无限**（最省事，街机味）；
2. **弹药物品化**：新增 70mm 火箭弹与陶氏导弹物品，R 键装填改为从背包取弹（改动大：新物品 + 装填交互 + 弹药架界面）；
3. **折中**：机场/基地附近（例如放在地上的补给箱）才能补弹。

### 6.3 燃料（建议不做）
飞机已经有血量这一个「资源」维度，再加燃油会让驾驶变成日常负担。建议**不做燃料**，把紧张感交给血量与坠毁损失。

### 6.4 修复与坠毁损失
- 修复：**无序配方** = 残血飞机 + 若干铁锭（每 20 点血 1 个铁锭）→ 满血飞机（只在背包里修，不需要新机器）；
- 已落地 6 条修理配方（2026-09-14）：小鸟 3、阿帕奇 5、F-35 5、Su-57 5、M1A5 6、IFV 5 铁锭。datagen 不输出“同名物品进、同名物品出”的无序配方，故手写在 `src/main/resources/data/battlefield/recipes/`，并由 `RepairRecipeTest` 锁定（type/产物/携带机体/铁锭数）。
- 坠毁：被打爆/撞毁后**掉一些废铁**（例如 2-4 个铁栏杆 + 1 个铁锭），让损失有痛感但不至于全损；
- 注意：现在 destroyAircraft 是**直接 discard、什么都不掉**，这条必须一起改。

4. HUD：两个面板都要显示各自弹药；补给中要有明显反馈（面板条推进）；
5. **已确认（2026-09-11）：7 = 待发总共 7 发**，42 = 备弹。两侧挂巢按 4/3 分摊这 7 发（先左后右轮转），
   也就是模型上会出现「14 个管子里只有 7 个装弹」的画面 —— 这是有意为之：待发弹仓只有 7 发，不是每侧 7 发。

## 11. 配方落地方式（决策 6）

已采用 **Forge datagen** 并跑通：

- 新增 data/ModDataGenerators（GatherDataEvent）+ data/ModRecipeProvider（配方与解锁条件）+ data/ModItemModelProvider（物品模型）；
- 命令：./gradlew runData，产物写入 src/generated/resources（build.gradle 早已把它作为资源目录）；
- 打开配方书的解锁顺序由 unlockedBy 决定：拿到铁锭 → 零件；拿到零件 → 整机；
- 生成器会在输出目录写一个 .cache 哈希缓存，已在 processResources 里排除，避免混进 JAR。

## 12. 固定翼三段组装与载具工厂（已实施，2026-09-14）

### 12.1 两架固定翼：11 材料拆成三段
- 缺陷：`f35`/`su57` 原为 **11 材料无序配方**，3x3 只有 9 格，永远不可合成；且两机材料逐项相同，即便放得下也无法区分。
- 修复：仿阿帕奇拆成三段，总成本不变（4 机身段 + 2 发动机 + 航电 + 座舱 + 2 挂架 + 火控）：
  - `f35_airframe` = "A A"/"ACA"/" V "；`su57_airframe` = "A A"/"AVA"/" C "（同材料、异布局 → 合成台可区分两机）；
  - `f35_weapons` = "P P"/" T "；`su57_weapons` = "PTP"；
  - `f35` = f35_airframe + 2×发动机 + f35_weapons（无序 4 格）；`su57` 同理。
- 入口：新增载具照此补两条中间件 + 整机配方即可。
- 回归：`RecipeGridTest` 遍历所有生成配方，无序 ≤9、形状 ≤3x3，并断言 6 台载具都有可合成配方。

### 12.2 载具工厂 battlefield:vehicle_factory（零件进、整机出）
- 方块 + 方块实体：9 格零件输入 + 1 格成品输出；漏斗可从任意面推入零件、只能抽走成品（`BlockEntity#getCapability` 暴露 `ItemStackHandler`，其 insert/extract 只放开单向）。
- 定时：纯规则表 `assembly/VehicleAssembly`（output/parts/ticks）每秒刻倒计时，完成后消耗零件并把整机物品放进输出格；表与生成配方由 `VehicleAssemblyTest` 交叉校验，改配方忘了改工厂会构建失败。
- 交互：手持零件右键投入；空手右键取成品；潜行空手倾倒输入；破坏方块掉落全部内容。
- 红石：比较器输出 0 空闲 / 1-14 进度 / 15 成品就绪。
- 合成：3x3 铁块 + 红石 + 工作台（"IRI"/"RCR"/"IRI"）。
- 待实测：6 台载具的建造时间手感、漏斗进出方向、比较器读数；GUI 未做（纯自动化交互）。
